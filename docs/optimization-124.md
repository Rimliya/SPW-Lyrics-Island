# 1/2/4 优化测试

基线为已通过测试的 `1.10.0-BASS-GPU @ b8f6b94`。该基线作为正式版；本轮仅在 `codex/1.10.0-fixes-124` 开发，测试包版本为 `1.10.1-test.1-BASS-GPU`。

## 1. 搜索失败与取消

- 成功返回空列表才进入两分钟负缓存；异常直接交给来源任务处理，不伪装成空结果。
- 等待共享请求的线程被中断时保留中断状态，原请求仍可被其它调用者使用。
- Provider 池任务持有连接取消作用域；取消或关闭任务时关闭 HTTP 连接、直接 HTTPS socket 和备用 DNS 请求。
- 已取消任务在返回、写搜索缓存前再次检查状态，Provider 自己吞掉异常也不能把取消结果写进负缓存。
- 播放 / 预取 / 批量的 4/2/2 Provider 并发不变。

## 2. 自动缓存重新校验

- 自动结果附带校验版本、参考歌词 SHA256 和相似度等级，来源排序继续沿用原 selectionKey。
- 指纹在歌词文档首次使用时计算并复用；普通 LRC 的完整参考解析复用本地读取快照，播放仍交给宿主。
- 缓存条件不匹配时，先用现有相似度算法重新比较；合格才更新校验记录，保留原保存时间与 TTL。
- 旧缓存按需校验，不提升整个缓存模型版本，不删除手动匹配；明确手动选择继续绕过自动校验。
- 校验记录采用条件更新，不能覆盖期间写入的手动选择；缓存目录不可写时，已验证结果仍可在内存使用。
- 播放、下一首预取、自动候选预览、质量升级和批量处理使用同一校验。批量列表只标记待校验，文件读取和比较在工作线程执行。
- 修改相似度设置会刷新当前自动结果；正在执行的旧条件结果不能写回当前缓存。

本轮没有调整不足五行歌词的判定、相似度阈值或来源排序规则。

## 4. 绘制区域回收

- 切歌、替换歌词或改变字体 / 翻译等高度相关设置时，重置预备高度。
- 预备任务按 generation 发布高度，旧任务不能把新曲目高度抬回去。
- 画布立即扩容；至少一个维度可减少 25% 且 64 个逻辑像素时，等待目标尺寸稳定两秒后缩容。
- 拖动、进度拖动、展开和歌词过渡动画期间不缩容；小幅尺寸变化保留容量。
- 缩容时释放旧软件像素缓存并重建所需缓冲，不改置顶 / 隐藏恢复，不重建 GPU 后端。
- Spout 独立尺寸与发送节奏不变；本轮没有合并桌面 / Spout 布局，也没有改变帧率策略。

## 验证

本地 56 项 JUnit 测试、`combinedChecks`、`spoutChecks` 已通过。

回归覆盖搜索失败重试、取消不负缓存、共享等待者中断、真实阻塞 HTTP 的连接关闭及 worker 复用；本地歌词改变、标准到严格设置、旧缓存升级、手动选择保护、批量重新验证；预备高度复位、动画保护、延迟缩容和立即扩容。

最终包由 Windows Actions 执行全部测试、Combined / Spout 自检和包校验后生成。实机还需验证：

1. 短暂断网后恢复，重试同一首的自动搜索。
2. 在音频副本上修改本地歌词，或把相似度从标准调为严格，确认不再直接沿用不合格自动缓存。
3. 确认手动选择、逐曲延迟、纯音乐跳过和元数据保存行为保留。
4. 大字号 / 高多行歌词后切回普通歌曲，等待两秒，检查边缘、悬停、拖动和全屏恢复。
5. 桌面与 OBS 同时播放，确认缩容不影响 Spout 尺寸、透明边缘与歌词动画。

尚未测量实机 CPU / 内存收益，自动测试不代表已完成这些视觉和宿主检查。
